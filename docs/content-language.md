# 網站與每日文章的繁體中文發布規範

## 語言與讀者介面

- **主要語言為臺灣繁體中文（zh-Hant）**。文章標題、描述、各級標題、內文、表格欄名、圖表標題／圖說、首頁與分類頁的可見文字，必須使用自然的繁體中文敘述。
- 站內顯示名稱使用「投資布局」「公司布局」「投資自己」「每日前沿」「軟體工程」；機器使用的路由及分類 slug（如 `investment-outlook`、`daily-digest`、`software`）不得因翻譯更動。
- 專有名稱可保留原文：GitHub、Reuters、Anthropic、CodeQL、Hugging Face、公司名稱、型號與協定；必要縮寫首次出現時以中文解釋。例如「自由現金流（FCF）」「回復時間目標（RTO）」「資料結構規格（schema）」。同一段落後續以中文為主，必要時保留縮寫。
- 程式碼區塊、實際 API／JSON 欄位、原始檔名、URL、股票代號、數學式與引用原文不硬譯，也**不會**用英文原文代替作者自己的中文分析。
- 避免無說明的英語工程口頭禪：`repo` → 儲存庫、`snapshot` → 快照、`dashboard` → 儀表板、`trace` → 追蹤紀錄、`fallback` → 備援方案、`async` → 非同步、`forward` → 前瞻、`schema` → 資料結構規格。引入新專業詞時，先解釋它在當日論點中的實際含義。
- 圖片中的可見軸、圖例與註解，除品牌和單位外也應採繁體中文；SVG 內的原始英文公司名及正式交易代號可保留。
- **校稿不能改變資料口徑**：不得翻譯掉程式碼欄位、來源 URL、財報單位、行情時間戳；不能因減少英文而省略技術細節、財報依據、反證或風險。

## 發布前檢查

1. 先寫中文論點、中文標題與摘要，再嵌入原始來源。
2. 搜尋各篇非程式碼敘述中的獨立英文術語，逐一改成中文，第一次必要時加英文括註。
3. 檢查首頁入口卡、分類標籤、圖表及文章標題有無突然切回英語。
4. 執行 `npm run validate:language`。此檢查會檢測近期期刊文章的標題、分類顯示名稱、英文術語及正文英文比例。它是**最低發布門檻**，不能代替人工通讀和內容事實查證。
5. 再執行 `npm run validate:investment`、`npm run build`，確認 GitHub Pages 成功部署。

研究輸入仍以 `docs/investment-outlook-method.md` 的獨立研究程序為準。語言偏好不是選股或選題指令。
