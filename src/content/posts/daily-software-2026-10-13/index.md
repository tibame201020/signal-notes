> 台北 10/13 凌晨截稿。昨日 10/12，近三日 10/10–12，近七日 10/06–12。

## 昨日新功能｜作者與真正推送者分開
GitHub 10/12 公布有限公開預覽：保存經驗證的**推送者身分**，與提交作者及提交者文字欄位分開；企業可設定提交者與推送者相符的規則。**目前限企業申請預覽，並非所有儲存庫預設啟用。** **依據：** [GitHub｜10/12 官方公告](https://github.blog/changelog/2026-10-12-push-attribution-public-preview/)。

**為什麼這樣判斷：** 提交作者文字可由客戶端填入；經驗證的推送者是另一種可稽核證據。自動化工具代為提交時，必須保存請求者、執行者與推送帳號的對應關係。

## 近七日｜本機沙盒與靜態掃描
GitHub 10/07 宣布 Copilot 本機沙盒正式提供，可限制工具存取檔案、網路與憑證；10/09 CodeQL 2.27.2 改進程式碼分析。**沙盒隔離、程式碼掃描、提交身分歸屬是三個不同控制點。** **依據：** [GitHub｜10/07 本機沙盒](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/)、[GitHub｜10/09 CodeQL](https://github.blog/changelog/2026-10-09-codeql-2-27-2-improves-c-go-rust-and-javascript-analysis/)。

**推論：** 企業應以可重現的執行政策與來源證據驗收自動化交付，而非只看工具生成的文字報告。**為什麼這樣判斷：** 靜態掃描不能證明某次實際部署的操作者身分，身分紀錄也不能取代執行權限限制。
