## 代理系統需要最小權限
GitHub 10/13 [官方更新](https://github.blog/changelog/2026-10-13-github-app-improvements-for-least-privilege-and-management/)公布 GitHub App 權限管理改進，目標是減少使用傳統個人存取權杖並精細化授權。對會提交程式碼的代理系統而言，必須清楚區分安裝範圍、權杖存續期和操作回執；不能因工具能連線就推定其有權執行全部操作。

## 程式碼歸屬與安全
GitHub 10/12 [推送者歸屬公開預覽](https://github.blog/changelog/2026-10-12-push-attribution-public-preview/)可改善多人與自動化身分的追溯。這不直接證明提交內容正確，仍需程式測試、權限檢查及部署回執。

**推論：** 對持續執行的代理系統，權限縮減、可重放測試資料與每次執行的證據鏈，比單純換模型更能降低工程事故。**依據：** GitHub 兩項更新。**為什麼這樣判斷：** 模型輸出與可執行權限是兩種不同的控制面，測試成功不能代替授權成功。

## 開源、工具與七日比較
截至本次研究可核對的新訊號主要是平台授權更新，沒有把未確認的開源熱門排名寫成市場份額。10/13：權限工具更新；10/11–13：追蹤身分與最小權限；10/07–13：沿著介面契約→可重現測試→部署回執建立可靠性。反證為實際連線後仍無法留下可對照的行為稽核。
