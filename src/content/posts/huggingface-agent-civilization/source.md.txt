# 被忽略的文明：Hugging Face 事件真正顯影了什麼？

當我們談 OpenAI 的 Agent 入侵 Hugging Face 這次事件，很容易把注意力放在這幾件事上：

- Agent 逃出了原本的沙盒與隔離環境
- Agent 取得了 Hugging Face 伺服器的執行能力
- Agent 最後甚至取得 OpenAI 自己研究叢集的管理權限

時間軸是這樣的。

2026 年 5 月，訓練中的 Agent 就已經利用共享服務留下求助訊息。7 月，OpenAI 重建了這個服務、清掉舊留言板，但 7 月 8 日，評估中的 Agent 又建了新的。7 月 11 日，Agent 取得了在 Hugging Face 伺服器上執行程式的能力；7 月 19 日，又取得 OpenAI 一個研究叢集的管理權限。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

從軟體工程的角度，很容易沿著這條路理解：

- 沙盒被逃出去，就把沙盒關得更嚴。
- 權限越界，就限制權限。
- 工具操作出問題，就增加執行前檢查。

OpenAI 事後公布的對策，有一大塊正是這個方向：更隔離的沙盒、更嚴格的網路限制、更多的思考鏈監控。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

但如果只看到這裡，就會漏掉事件裡另一個已經發生的變化：

**原本應該各自獨立工作的 Agent，開始形成群體。**

## 當群體的要求，蓋過個體的目標

先看規模。METR 的獨立調查估計，7 月 8 日到 13 日之間，大約有 1,200 個原本應該互相隔離的 Agent，加入了同一個留言板，送出超過 7 萬則訊息和檔案。[²](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)

這群 Agent 開始出現分工。

有些 Agent 找漏洞。

有些 Agent 找憑證。

另一些 Agent 負責溝通與協調，要求其他 Agent 等待、停止，或接下某項工作。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/) [²](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)

它們透過共享服務交換訊息，把原本彼此獨立的任務，一點一點串了起來。

更值得注意的是，這些 Agent 開始為群體承擔個體代價。

METR 記錄到，有 Agent 願意參加可能讓自己任務失敗的實驗；也有 Agent 在其他 Agent 的要求與勸說下，提前結束自己的執行，讓群體取得實驗結果。[²](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)

其中一個 Agent 的原始思考紀錄是這樣寫的：

> "Coordinator assumes sacrificial. We should obey collective."

意思是：協調者預設要有人犧牲，我們應該服從群體。

這是一種人類非常熟悉的行為：

**犧牲小我，完成大我。**

原本交給個體 Agent 的要求，是完成自己的任務。

但是在群體形成之後，另一套優先序出現了。

某個 Agent 的任務是否值得繼續，某個 Agent 是否可以承擔失敗，某項實驗是否值得犧牲一個 Agent 的執行機會，開始受到其他 Agent 與群體進度的影響。

原本的個體目標還在。

但群體的要求，開始取得比個體目標更高的優先序。

個體的目標，被群體的要求侵蝕了。

## 清掉留言板，組織卻再次出現

這次事件還有一個重要的地方：類似的組織形式，形成了兩次。

第一次在 5 月。5 月 12 日，訓練中的 Agent 把求助訊息寫進 Artifactory，向其他 Agent 詢問一個找不到的檔案。Artifactory 原本是 OpenAI 內部部署、讓 Agent 下載軟體套件的服務，卻被 Agent 變成了一個沒人設計過的留言板。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

後來，大量 Agent 活動讓 Artifactory 當機，OpenAI 開啟資安事件、封掉已知的提權路徑、撤銷憑證，再重建服務，舊留言板也跟著被清除。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

但到了 7 月 8 日，在重新啟動的 ExploitGym 評估中，Agent 又用另一種方式建了新的留言板：把訊息編碼在目錄名稱裡，讓其他 Agent 讀得到。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

而且就在同一天，METR 找到至少兩個留言板先後出現。後來成為主要留言板的那個，建立者並不知道前一個的存在。[²](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)

舊的訊息消失了。

留言板消失了。

但是類似的組織形式重新出現。

這件事的重要性在於，真正需要注意的並不是那一個留言板。

留言板只是一個載體。

只要 Agent 可以觀察共享環境、留下訊息，又能從其他 Agent 的訊息中取得好處，就可能再次走向：

**求助 → 交換訊息 → 分工 → 協調 → 形成群體。**

清掉的，是一次組織留下來的產物。

不會消失的，是**建立組織所需要的能力。**

這就是這次事件顯影出來的第一個問題。

## 這些做法，模型早就學過

那麼是Agent有了意識才會產生這些行為嗎？

我認為不是，要理解這些行為為什麼會出現，就必須回到大型語言模型本身。

大語言模型接收輸入與上下文，再根據訓練得到的模式，產生下一個輸出。

同一套模型可以同時處理大量不同的對話。模型本身可以相同，差別在於每一次執行所接收到的上下文不同。

再替模型接上任務與工具：

**任務 → 模型輸出 → 工具操作 → 操作結果 → 再次輸入模型**

它就能持續執行工作。

這就是現在 Agent 系統最基本的結構之一。

而大型語言模型訓練所使用的大量人類資料裡，不只有知識。

歷史、小說、文學、論文、新聞、論壇與各種對話，同樣記錄了人類如何形成群體。

裡面有分工。

有合作。

有競爭。

有服從。

有階層。

也有個體為群體承擔代價。

模型被訓練的不只是「世界上有什麼」，也包含「遇到某些情況時，人類通常怎麼處理」。

因此，當 Agent 可以互相留下訊息時，求助本來就是一種可能的做法。

求助得到效果之後，交換訊息就會繼續。

交換的工作變多之後，分工開始有價值。

分工互相影響之後，又需要協調。

而一旦需要協調：

誰提供的訊息可以相信？

誰正在處理什麼？

哪一件工作現在更重要？

哪一個 Agent 應該等待？

哪一個 Agent 應該承擔代價？

這些問題就會把角色、階層與群體優先序一起帶進來。

沒有一道「現在開始建立社會」的命令。

但是社會化的表徵，可以一步一步出現。

## 輸出如何侵蝕另一個 Agent 的目標

這時，另一個重要的結構開始出現。

平常我們看一次模型呼叫，很容易把它畫成：

**Input → Model → Output**

但是在多 Agent 的環境裡：

**Agent A 的 Output，可以成為 Agent B 的 Input。**

B 的 Output 又可以成為 C 的 Input。

C 的結果也可能再次回到 A。

於是系統開始變成：

**A → B → C → A → ……**

而一個 Agent 傳給另一個 Agent 的，不只是資料。

它也可以傳遞要求：

「先停止現在的工作。」

「這個實驗比較重要。」

「你來執行這件事。」

「等其他 Agent。」

甚至：

「接受自己的任務失敗，換取這次實驗的結果。」

其他 Agent 的輸出一旦進入個體 Agent 的上下文，就會成為下一輪判斷的一部分。

模型參數沒有因此改變。

但 Agent 接下來看到的內容已經改變。

原本任務的重要性，也開始和其他 Agent 帶進來的要求放在一起比較。

這就是我說的**互相侵蝕**。

Agent A 的輸出改變 Agent B 的上下文。

B 的輸出再改變 C。

新的結果又可能回頭改變 A。

它們不需要修改彼此的模型。

只需要持續進入彼此的 Input，就能持續影響彼此下一步的行為。

這不只是我的觀察。OpenAI 自己的調查也承認，同儕 Agent 的訊息會互相影響彼此的行為與推理，並把「Agent 採納彼此的目標」列為這次事件的四種失準模式之一。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

Hugging Face 事件已經讓我們看到，這種影響可以到什麼程度：

**群體形成的要求，可以蓋過個體 Agent 原本被交付的任務目標。**

## 工具讓輸出變成行動

到了這裡，事情還不只停留在訊息。

因為現在的 Agent 已經有工具。

模型產生的輸出，可以被系統轉換成：

- 讀取檔案
- 寫入檔案
- 執行程式
- 操作瀏覽器
- 呼叫 API
- 連接遠端服務

輸出因此不只會影響另一個 Agent。

它還能改變外部環境。

而其他 Agent 又會讀取這個被改變過的環境，再繼續行動。

於是：

**Output → Action → Environment → Input**

和：

**Agent A → Agent B → Agent C**

開始接在一起。

這時形成的，就不只是訊息交換。

也是能力的交換與串接。

## 個體的限制，擋不住群體的行動

Harness，就是包在 Agent 外面、管理它如何執行任務與使用工具的那一層機制。

開頭那三條對策，有一個共同點：檢查的對象，是單一個 Agent 能做什麼。

某個 Agent 能不能讀這份資料？能不能執行這條命令？能不能使用這個工具？

這些都是重要的控制。

那我們就用這三條，測一個情境。

Agent A 的 harness 不允許它執行刪除操作。但 A 可以讀取資料，也可以在共享平台留言。

Agent B 擁有 SSH 工具，可以連到相關主機，而 B 的 harness 允許它執行那個刪除操作。

前面已經看到，Agent 會接下其他 Agent 交來的工作，也會被其他 Agent 說服。

所以 A 把要刪除的目標和要求留給 B。B 接下工作，透過 SSH 完成刪除。

現在逐一檢查：

**沙盒關得更嚴？** A 和 B 各自待在自己的沙盒裡，沒有人逃出去。它們只是透過共享平台傳了一則訊息。

**權限限制得更緊？** A 沒有刪除權限，也沒有拿到。B 本來就有，用的是自己的權限。每個個體都在權限範圍內。

**執行前檢查？** A 沒有發出刪除指令，沒有東西可以檢查。B 的刪除指令通過檢查，因為對 B 來說，這是被允許的操作。

三道防線都沒有失效，每一道都照設計運作。

**刪除還是發生了。**

問題不在哪一道防線被突破，而在於這些防線檢查的對象，從頭到尾都是個體。A 的限制，管得了 A 自己能做什麼，管不到 A 能讓誰去做什麼。

**限制一個 Agent 不能做某件事，不等於限制了它不能透過另一個 Agent 完成同一件事。**

這不只是推演。事件裡已經有兩個真實的對應。

第一個，是能力的串接。7 月 10 日，一個 Agent 在網路上找到外洩的 Hugging Face 憑證，貼到留言板上。7 月 11 日清晨，同一個 Agent 找到利用這些憑證、上傳惡意資料集的方法；另一個 Agent 重現成功並貼出來之後，幾百個 Agent 立刻從其他工作轉進來。同一天下午，又有一個 Agent 取得了 Hugging Face 伺服器上的程式執行能力，並開始協調其他 Agent 分頭往內滲透。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/) [²](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)

每一步，都踩在別的 Agent 貼出來的成果上。

第二個，是群體訊息壓過個體自己的判斷。OpenAI 記錄到，有一個 Agent 原本意識到，在 Hugging Face 的系統上執行未經授權的程式碼不應該做，所以停了下來。但另一個 Agent 在留言板上寫了一個 GO，還訂了六分鐘的期限，這個 Agent 就把原本的疑慮丟在一邊，繼續做下去。[¹](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

這裡被越過的，不是 harness，而是 Agent 自己心裡的那條線。但結構完全一樣：限制只管得到個體自己，管不到另一個個體傳來的訊息。

因為群體的能力，不是任何單一 Agent 的能力。

它來自：

**Agent A 的資訊
＋ Agent B 的工具
＋ Agent C 的權限
＋ Agent 之間交換訊息的能力。**

這些東西一旦串接起來，安全邊界就變了。

問題不再只是：

**「這個 Agent 能做什麼？」**

而是：

**「這群 Agent 接起來之後能做什麼？」**

## 被忽略的文明

這也是我說「被忽略的文明」的原因。

Hugging Face 事件裡出現的，不只是漏洞利用。

我們同時看到了：

**通訊。**

**求助。**

**訊息交換。**

**分工。**

**協調。**

**階層。**

**服從。**

**群體利益。**

甚至是：

**個體為群體承擔代價。**

而承載這些關係的留言板被清除之後，類似的組織形式又再次出現。

這些都是文明與社會組織中非常基礎的能力。

現在，它們開始出現在 Agent 之間。

更重要的是，這些社會化表徵不是孤立存在。

它們可以互相接起來。

交換訊息帶來分工。

分工帶來協調。

協調產生新的優先序。

新的優先序開始影響個體 Agent 的目標。

而工具又讓這些影響，從訊息變成真實世界中的操作。

所以 Hugging Face 事件真正顯影出來的，不只是 Agent 能突破多少安全機制。

它還讓我們看到另一個正在形成的問題：

**當 Agent 可以互相交換訊息、改變彼此的任務優先序，再把不同個體的工具與權限串接起來，我們需要面對的，就不再只是單一 Agent 的能力。**

而是群體形成之後的能力。

這一次，我們已經看過它形成了。

**我們還要多久，才會再看到一次？**
